# Проверки ModbusTCP_RU

## Host regression tests

Нужны C++11-компилятор и PowerShell 7 (Windows или Linux):

```powershell
./tests/run.ps1 -Compiler g++
```

На Windows с MSYS2 можно указать `C:\msys64\mingw64\bin\g++.exe`. Результаты сборки остаются во временной папке, путь печатает скрипт. Репозиторий не засоряется бинарниками.

Проверяются профили SMALL, FULL и SMALL с буфером 64 байта; границы FC01/02/03/04/05/06/15/16, MBAP, callbacks, два клиента, заполнение пула, фрагментация, несколько ADU в потоке, lifecycle, таймауты и переполнение millis. Отдельные compile/link probes проверяют запрет небезопасных конфигураций и удалённых overloads.

Используется настоящий ModbusTCP_RU.cpp и модель Ethernet 2.x из `host/Ethernet.h`. Она моделирует владение сокетами и занятость TX, но не SPI, PHY, retransmissions, время ожидания аппаратного SEND_OK или AVR bootloader. Размеры типов host и AVR отличаются; поэтому нужны обе группы проверок.

## Arduino

CI собирает все пять примеров для Nano ATmega328P Old Bootloader с Ethernet 2.0.2 и GyverHTU21D 1.1.2. CI-проверки не прошивают устройство.

## Стенд

Для 0.3.0 пользователь подтвердил на Arduino UNO + Ethernet с проектом ScadaRelayTimer стабильный обмен через Modbus Poll и повторное подключение после отключения питания, перезагрузки и возврата патч-корда. Тип Ethernet-чипа в этой проверке отдельно не зафиксирован. Проверка не заменяет длительный прогон, испытания других модулей и датчиковых примеров.

После установки 0.3.0:

1. FC04 и FC03 с опросом 1000 мс, затем 200 мс.
2. Два независимых TCP-соединения; совпадение TID и отсутствие потери ответов.
3. Отключение кабеля на 1/10/60 секунд; автоматическое новое подключение без перезагрузки AVR.
4. Подключение без первого запроса и освобождение по idle timeout.
5. Повторные begin/restart без накопления слушающих сокетов.
6. Таймер реле и EEPROM под сетевой нагрузкой, затем длительный прогон.
7. HTU21D отсутствует при старте, отключён в работе и подключён повторно: Modbus продолжает отвечать, значения ошибки сменяются свежими измерениями.

Реле проверять на безопасной нагрузке. Повреждённые пакеты не отправлять в действующее оборудование. Измерять максимальное время loop/MbsRun: EthernetClient::write остаётся потенциально блокирующим.
